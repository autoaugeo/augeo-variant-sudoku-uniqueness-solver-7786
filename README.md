# Variant sudoku solver, generator and verifier

This project is built and maintained by an automated agent system.

The puzzles, the solver and the book PDF are generated by an automated AI agent
system. This repository holds the tools that produce and check the puzzles:
pure Python 3, standard library only, no network access, no subprocesses.

## Files

- `solver.py` - bitmask backtracking solver with minimum-remaining-values cell choice.
- `generate.py` - writes puzzles, each with exactly one solution, to a JSON file.
- `verify.py` - re-checks puzzle JSON files from scratch.
- `tests/run_tests.py` - plain-assert tests (no pytest).
- `samples/sample_puzzles.json` - 10 sample Sudoku X puzzles with solutions.
- `LICENSE` - MIT licence (applies to the code in this repository).

## Variants

Every variant keeps the normal rows, columns and 3x3 boxes and adds one rule:

| name | extra rule |
| --- | --- |
| `x` | both main diagonals hold 1-9 |
| `windoku` | four extra 3x3 regions (0-based top-left corners r1c1, r1c5, r5c1, r5c5) hold 1-9 |
| `antiknight` | cells a chess knight move apart hold different digits |
| `antiking` | cells a king move apart, diagonal neighbours included, hold different digits |

A grid is an 81-character string read row by row; `0` marks an empty cell.

## Solver API

```python
import solver

solver.peers("x")                      # 81 tuples: cells that may not repeat a cell's digit
solver.count_solutions(grid, "x", 2)   # exhaustive count, stops at the limit
solver.solve(grid, "x")                # first solution string, or None
solver.is_unique(grid, "x")            # True only when exactly one solution exists
solver.check_solution(full_grid, "x")  # True for a complete grid that breaks no rule
```

## What the solver does

`solver.py` counts solutions exhaustively for four variants of
[Sudoku](https://en.wikipedia.org/wiki/Sudoku): Sudoku X (diagonals), Windoku
(four extra windows), Anti-Knight and Anti-King. The search explores every
branch and stops only when it has found the requested number of solutions, so a
count of exactly 1 means the puzzle has a single solution.

## Run

Generate puzzles (these are the exact arguments and seeds used for the 300-puzzle
book: 75 puzzles per variant):

```
python3 generate.py --variant x --count 75 --seed 101 --time-limit 100 --out puzzles_x.json
python3 generate.py --variant windoku --count 75 --seed 202 --time-limit 100 --out puzzles_windoku.json
python3 generate.py --variant antiknight --count 75 --seed 303 --time-limit 100 --out puzzles_antiknight.json
python3 generate.py --variant antiking --count 75 --seed 404 --time-limit 100 --out puzzles_antiking.json
```

Verify a puzzle file (re-solves every puzzle from scratch and checks the stored
solution):

```
python3 verify.py puzzles_x.json
```

Run the tests:

```
python3 tests/run_tests.py
```

The tests include a check that the 10 puzzles in `samples/sample_puzzles.json`
(the first 10 Sudoku X puzzles of seed 101) each have exactly one solution.

## Printable book

A printable 300-puzzle book made with this code exists (75 puzzles for each of the
four variants). It is a separate product; this repository is complete and useful
without it.

`generate.py` builds a random full grid with a seeded randomized depth-first
search, then removes givens in seeded random order, keeping a removal only if the
puzzle still has exactly one solution. It stops at 30 givens or fewer, or when the
per-puzzle share of `--time-limit` is used up, and it stops cleanly before the
time limit and writes what it has. Without `--out` the file goes to
`/out/puzzles_<variant>.json` if `/out` exists, otherwise to the current
directory. It prints `generated <count>/<requested> variant=<v> seconds=<t>` and
exits 0 when all requested puzzles exist, or 3 when fewer were made (the file is
still written). Puzzle ids use the prefixes `X`, `W`, `KN` and `KG`.

Output format: `variant`, `seed`, `requested`, `count`, and `puzzles`, a list of
`{id, variant, givens, solution, n_givens, solutions_found}`.

## What "proven unique" means here

For each puzzle a script runs an exhaustive backtracking search that explores
every branch and stops as soon as it finds a second solution. If the search ends
having found exactly one, the puzzle is recorded as unique; if it finds two it is
rejected. The generator applies this check after every removed given and once
more on the final puzzle. `verify.py` repeats the check independently for each
stored puzzle, and also confirms that the stored solution is that solution, obeys
the variant rules and agrees with the givens. The claim is only as strong as the
solver code in this repository, which is short enough to read, and the tests in
`tests/run_tests.py`.
